# DISEÑO RESUMIDO BASADO EN CONCURRENCIA / PI-CALCULUS

## 1. Procesos principales

El sistema se divide en procesos que trabajan en paralelo:

### 1. Parameter Server (PS)
- Guarda y actualiza los parámetros del modelo: $$w, b$$.
- Recibe gradientes desde los Workers.
- Agrega gradientes y envía los nuevos parámetros a todos los Workers.

### 2. Workers
- Procesan subconjuntos de datos (minibatches).
- Reciben los parámetros de PS.
- Calculan gradientes $$ (dw, db) $$.
- Envían gradientes al PS.

### 3. DataLoaders
- Entregan minibatches cuando un Worker los solicita.
- Cada DataLoader maneja una partición de datos.

### 4. Coordinator
- Controla epochs, inicio y final del entrenamiento.
- Puede monitorear MSE, recibir métricas, ordenar fin del proceso.

---

## 2. Canales de comunicación

Se definen canales donde los procesos envían/reciben mensajes:

- **params:** PS → Worker (envío de parámetros $$w, b$$).
- **grad:** Worker → PS (envío de gradientes).
- **req_batch:** Worker → DataLoader (pedir minibatch).
- **batch:** DataLoader → Worker (entrega de minibatch).
- **log:** PS o Workers → Coordinator o Monitor.

---

## 3. Flujo general del entrenamiento (versión resumida)

### 1. Inicio
- PS inicializa $$w = 0, b = 0$$.
- Coordinator indica cuántos epochs se van a ejecutar.
- Todos los Workers esperan parámetros.

### 2. Ciclo por epoch
Para cada epoch:

**(a)** El PS envía los parámetros a todos los Workers  
PS → params → Worker: $$(w, b)$$

**(b)** Cada Worker solicita un minibatch  
Worker → req_batch → DataLoader  
DataLoader → batch → Worker

**(c)** Worker calcula gradientes con su minibatch:

$$dw = \frac{2}{m} \sum (y_{pred} - y)x$$  

$$db = \frac{2}{m} \sum (y_{pred} - y)$$  

**(d)** Worker envía gradientes al PS  
Worker → grad → PS: $$(dw, db)$$

**(e)** PS agrega gradientes  
Si hay $$W$$ workers:

$$dw_{total} = \text{promedio}(dw_j)$$  
$$db_{total} = \text{promedio}(db_j)$$  

**(f)** PS actualiza parámetros:

$$w \leftarrow w - \eta \cdot dw_{total}$$  
$$b \leftarrow b - \eta \cdot db_{total}$$  

**(g)** PS reporta métricas (opcional)  
PS → log: mse_epoch

### 3. Finalización
- Cuando Coordinator decide (por epochs o MSE):
  - Envía un mensaje **terminate** a todos.
  - Workers y DataLoaders cierran sus procesos.

---

 ## 4. Características del diseño
- Paralelismo natural: múltiples Workers calculan gradientes simultáneamente.
- Sincronizado o asíncrono:
  - **Síncrono:** PS espera todos los gradientes.
  - **Asíncrono:** PS actualiza a medida que llegan.
- Escalable: se pueden agregar más Workers sin cambiar el diseño.
- Evita estados compartidos: todo pasa por canales, como dicta el cálculo π.
